# WD World 1.7 使用说明

双击同目录的 `WD World.exe` 即可使用，不需要浏览器、Python 或 Node.js。移动软件时保留整个目录。

启动时先选择“小说 AI 辅助”“OC 创作者”“TRPG 主持人”“酒馆制作”或“自由模式”，再新建或打开世界。各模式分别显示自己的项目，每个项目拥有独立的世界观与草稿。旧项目默认归入自由模式。导入备份保留其模式归属；无模式信息的旧备份归入自由模式。

专用模式项目打开后直接进入对应创作界面：小说创作旅程、OC 创作者、TRPG 主持人或酒馆制作。“世界观设定”始终可在顶部切换进入。自由模式开放全部工具，默认进入世界观。菜单栏“文件 → 切换创作模式”（Ctrl+Shift+M）会保存并关闭当前项目和局域网房间，再返回模式选择；生成期间先停止或等待完成。

## 自动互动、场景卡与 TRPG 副本

酒馆开房默认勾选“玩家发言后自动回复”和“玩家入场自动开场白”。开房前选择角色卡，已有场景自动作为房间公开场景。每位新加入的玩家收到替换了 `{{user}}` / `{{char}}` 的开场白；浏览器刷新复用登录，不会再次发送。后台自动使用房主已保存的模型配置，切换创作页面仍会回应。场外交流不触发 AI，AI 回复和开场白也不会触发递归回复。连续发言合并处理，避免同时发布过期回答；生成失败后暂停自动回复，在房主界面显示原因，修改配置后点“应用自动互动设置”恢复。

“暂停 AI 并接管”取消未发布生成，保留玩家发言功能；“暂停跑团或对话”同时暂停玩家的角色发言和掷骰，OOC 仍可用。“主持人干预并暂停 AI”发布输入框中的叙事并接管。主持人也可填写引导、手动生成预览、编辑后发布。切换 AI 角色或备用开场白后，点“应用自动互动设置”更新后台配置。房间结束或切换项目时取消后台生成，旧回复不会进入新房间。角色被玩家认领后，AI 不再代其发言。

“酒馆制作 → 角色场景卡”可保存当前角色、收藏角色、场景、开场白和世界书为一套卡片，预览载入及导入／导出 `.scenario.json`。联机中可“保存房间为场景卡”，保存当前公开场景和选定角色，不包含玩家身份与聊天记录。已有 V2 / 旧版角色卡 JSON 导入导出继续使用“角色卡工坊”；当前未加入 PNG 角色卡。场景卡随项目每 10 秒加密保存及完整项目备份，最多 100 张。

“TRPG 主持人 → TRPG 副本与世界库”提供“一键随机 TRPG 世界”，按已有资料和种子生成完整世界与副本；空白项目可直接随机。生成结果进入世界观待确认，采纳后载入备团草稿，保留实际跑团记录。预设三套原创、无系统短篇：奇幻探索《雾钟遗迹》、悬疑调查《无声旅馆》、科幻求生《最后一班信标》，包括场景分支、NPC、线索、遭遇与主持人秘密，可按所用规则改编。

支持选择保存的副本、导入 TRPG 副本 JSON、世界观导出 JSON、TXT 和 Markdown（最大 2 MB）。导入先预览，确认后同步设定并加入本项目副本库。文本资料载入主持人的场景草稿，玩家可见背景留空，避免直接公开整份模组。当前不直接解析 PDF / Word。导出的副本 JSON 不包含实际跑团记录；本项目副本库和完整备份保留各自资料。

TRPG 开房使用“玩家可见背景”作为公开场景与入场开场白。玩家发言、掷骰后自动生成叙事回应；模型只接收公开场景、已发布资料、规则名称、玩家资料、近期对话及主持人引导，不自动读取秘密、未揭示线索和备团全文。主持人根据进度发布线索或主动介入；检定结果来自房间骰子，AI 不自动修改 HP、先攻或设定。秘密不会直接出现在浏览器响应中。

## 整套酒馆世界与设定自动入库

酒馆 AI 区域新增“随机生成整套酒馆世界”。没有种子时自动产生一个，有资料时依据已知设定扩展，空白时从零起稿。一次生成世界背景、规则、地点、阵营、剧情引子、多个有关联的角色及配套世界书。结果完整解析后显示分组预览；“采纳整套世界与角色卡”会将角色加入收藏库、载入首个角色草稿和世界书。若生成期间草稿或收藏发生修改，采纳会被阻止以保护编辑。

小说的人物／规则建议、OC 角色、TRPG 备团设定、酒馆角色与世界书，以及世界推演建议，生成后自动加入世界观列表，状态为“AI 待确认”。这些条目在确认前不会进入 AI 的已确认资料或解锁小说后续阶段。模式内采纳／逐条确认后转为正式设定；对已有条目的变更仍需逐条确认，确认后收起其待确认副本。正文、章节摘要和实际跑团记录不作为新设定批量入库。手动输入的草稿继续按原工作流处理。

同名但内容不同的建议作为独立候选保留，不覆盖已有正文；相同名称、类型及正文的条目复用，避免重复入库。世界观条目为项目私有资料，局域网仍需房主明确发布才对玩家可见。本地开发版项目与草稿继续可读；旧候选不会自动批量迁移，重新生成即可使用自动入库。

## 局域网 TRPG 与酒馆

### 酒馆制作与多人扮演

- 在“酒馆制作 → 角色卡工坊”导入 V2 / 旧版角色卡 JSON、独立世界书 JSON。导入先预览；确认角色卡会替换当前草稿及世界书，独立世界书则追加。需要保留旧草稿时先收藏。当前不支持 PNG 角色卡或脚本插件导入。
- 扩展字段支持创作者、版本、标签、备用开场白（用独立一行 `---` 分隔）、角色提示词、对话后置提示词。V2 扩展数据和导入世界书的高级字段保留用于导出；本机匹配仅支持常驻及不区分大小写的普通关键词，不执行正则、递归触发或概率规则。
- “收藏当前角色卡”保存角色卡和绑定世界书的独立副本，最多 100 张。可预览载入、更新所选收藏；收藏和随机种子一起加密保存在项目中，也随完整项目备份导出。
- “世界书触发测试”输入对话后显示会匹配的正文。房间生成 AI 回复使用同样的匹配方式，扫描公开场景及最近非 OOC 对话。
- 房主从当前草稿或收藏库选择“AI 发言角色”。如需玩家认领，先预览公开角色名称与描述，编辑后确认发布；备注、世界书和未发布角色不会下发给浏览器。每个角色仅一名玩家认领，每名玩家同时认领一个角色；释放、离开、被移出或撤下角色后允许重新分配。最多发布 40 个角色。
- 场外交流（OOC）单独标记，不进入 AI 对话上下文。暂停角色扮演后玩家仍可使用 OOC。房主不能让 AI 代替已认领角色发言；生成后如房间已有新消息或角色等变化，需要重新生成，服务端也会拒绝过期回复。
- 选择默认或备用开场白，再载入场景草稿、检查后发布。载入时替换 `{{char}}` 为角色名、`{{user}}` 为当前玩家角色名称；没有玩家时保留占位符。

### 创作随机种子

小说、OC、TRPG、酒馆与世界推演的 AI 区域都有“创作随机种子”。点击“换一个种子”或手动输入后，再点击原有生成按钮。有资料时保留已知事实、补充随机灵感；空白 OC / TRPG / 酒馆草稿以及小说 01 可以直接起稿。自由模式可以使用所有这些工具。

种子控制可复用的灵感组合，通过提示词兼容各模型服务，不要求服务商支持采样 seed 参数。同一种子与模式提供相同方向，不保证模型逐字输出一致。小说仍遵守阶段资料隔离；摘要与矛盾检查不注入随机灵感。世界推演仍需已有世界条目，可不填写变更条件，由种子提出假设，再逐条确认。随机结果不会自动改写正式设定或实际跑团记录。关闭随机后恢复普通辅助创作。

制作流程参考：[SillyTavern 从入门到精通](https://www.rainlain.com/index.php/2024/11/19/2645/)、[World Info 官方文档](https://docs.sillytavern.app/usage/core-concepts/worldinfo/)、[Character Card V2 规范](https://github.com/malfoyslastname/character-card-spec-v2/blob/main/spec_v2.md)。本工具实现上述明确列出的功能，不等同于完整 SillyTavern 引擎。

### 开房与保存

1. 房主使用桌面版，在 TRPG、酒馆或自由模式中打开项目，点击“局域网房间 → 创建房间”。
2. 玩家设备连接同一局域网，在浏览器输入房主显示的网络地址（例如 `http://192.168.1.5:端口`），填写房间码和玩家名称。`127.0.0.1` 地址仅限房主电脑本机使用。
3. 每个房间最多 16 名玩家。玩家可以设置自己的角色名称、公开描述、HP 和最大 HP，参与聊天和掷骰。支持 `1d20`、`2d6+3` 等表达式，骰子由房主程序生成并同步。
4. TRPG 房主可以发布场景、资料和先攻顺序（每行 `名称 = 数值`），锁定加入或移出玩家。世界条目先载入草稿，确认后才公开；主持人秘密、其他未发布条目、API 配置不会发送给玩家。发布过的资料即使撤下，已阅读或复制的内容也无法收回。
5. 酒馆默认在玩家发言后调用房主模型自动回复，也可关闭自动回复并手动预览发布。AI 使用选定角色卡、常驻或关键词匹配的世界书、公开场景及最近 40 条非 OOC 消息；创作者备注不发送。后台匹配世界书最多取 20,000 字符，整体过长时使用现有分段整理。玩家不能更改 AI 配置或房主资料。
6. 最近 300 条消息和公开资料每 10 秒加密存档；“手动保存记录”和“结束房间”也会保存。TRPG 手动保存或结束房间时将当前记录写入“实际跑团记录”。“读取历史记录”可查看和导出已存档房间。结束房间后监听关闭、加入令牌失效；重启不会自动开房。

房间使用 HTTP，适用于可信局域网，没有传输层加密。房间码限制加入，不能代替可信网络。程序不会修改防火墙或设置公网端口转发；连接不通时检查 Windows 的专用网络防火墙许可。电脑必须保持运行。同机多浏览器客户端测试已覆盖，但不同路由器、访客网络隔离和系统防火墙仍需在实际网络确认。

## 创作模式

- **世界观设定**：自由模式默认入口，管理人物、地点、组织、物品、事件、规则等条目，使用百科、地图、关系图和时间轴。
- **OC 创作者**：填写角色概念、外貌、性格、目标、经历、关系与成长弧线。AI 生成时同步世界观待确认条目，采纳后确认。手动草稿可以“确认新建人物条目”。同名人物不会自动覆盖，请回到世界观编辑。
- **TRPG 主持人**：填写规则系统与版本、玩家背景、引子、场景分支、NPC、线索、遭遇、主持人秘密和实际跑团记录。制作页 AI 辅助备团，采纳时保留实际跑团记录；局域网提供自动叙事与主持人干预。可导出主持人 Markdown、副本 JSON；“导出玩家背景”仅包含玩家背景字段，不附带主持人秘密。
- **酒馆制作**：制作角色卡、世界书与角色场景卡，并通过局域网房间自动互动。填写描述、性格、场景、开场白、示例对话和备注，支持 `{{char}}` / `{{user}}`。可从 OC 草稿填充空白字段，导出 Character Card V2 JSON，并附带当前世界书。世界书支持手动新建或复制所选世界条目，编辑触发词、正文、启用状态、常驻和插入顺序，另可导出 SillyTavern 世界书 JSON。当前提供 JSON 导出，不包含 PNG 嵌入卡或第三方酒馆直接同步。

OC、TRPG、酒馆与推演页面都有每 10 秒自动保存和“保存本页”。各模式独立选择参考条目，默认选择全部已确认、非归档条目；发送前可预览具体资料。草稿写入当前模式，提取出的设定进入世界观。其他模式草稿不会直接混入，但共享世界观中的已确认资料可被选为参考。导出文件是明文，请妥善保管。

酒馆导出依据：[Character Card V2 规范](https://github.com/malfoyslastname/character-card-spec-v2/blob/main/spec_v2.md)、[SillyTavern 世界书说明](https://docs.sillytavern.app/usage/core-concepts/worldinfo/)、[世界书字段实现](https://github.com/SillyTavern/SillyTavern/blob/release/public/scripts/world-info.js)。

## AI 辅助推演世界变更

1. 在世界观中建立基础条目，打开顶部“推演世界变更”。
2. 填写拟发生的变化、推演时间范围和必须保持不变的规则，选择参考条目。
3. 点击推演，查看因果分析、直接和间接影响、可能分支、不确定性及条目正文的修改前后对照。长资料继续使用分段整理。
4. 逐条编辑建议并确认，或拒绝建议。生成时建立待确认副本，确认前不修改原有条目正文；确认后更新目标正文并收起待确认副本，不自动删除正式条目或重写关系。
5. 已确认的变更可撤销，恢复原正文。目标条目在推演后或确认后已有其他修改时，会阻止覆盖或撤销，需重新推演。推演记录与操作状态随项目加密保存，并包含在完整备份中。

推演是创作假设，不是既定事实。确认时仍应核对规则与证据；已确认条目之外的连锁影响仅保留为分析。

## 小说 AI 辅助

小说模式的创作旅程按顺序推进：故事想法、人物与规则、故事大纲、拆分章节、辅助写作、检查矛盾、确认设定。完成前一阶段的必要内容后解锁后续步骤，随时可以返回已解锁的页面修改；也可以全部手动完成。

01 的 AI 只处理故事想法；02 根据 01 设计人物与规则，并在 02 本页逐条确认；03 使用 01 和 02 的已确认内容；04 再加入 03 大纲；05、06 加入章节计划、当前正文与前文摘要。后面阶段的正文、检查结果或待确认建议不会混入早期阶段。07 由作者逐条确认更新。

## 手动创作

- 输入故事想法、类型与文风，随时自动保存。
- 在“人物与规则”手动建立人物和规则。“世界资料库”保留原有百科、地图、时间轴、关系图、模板和条目编辑功能。
- 在“大纲”直接写故事结构；在“拆分章节”新建、排序、删除章节，填写卷名和章节计划。
- 在“辅助写作”编辑正文、标记完成、填写供后文参考的章节摘要，导出整部小说的 Markdown。
- 在“检查矛盾”可以自行记录问题、原文出处与修改建议，并标记处理状态。

## AI 辅助

打开右上角“AI 设置”，按以下步骤连接模型：

1. 选择 DeepSeek、小米 MiMo、OpenAI / Codex、Google Gemini，或自定义 / 本地模型。服务商地址会自动填入，也可修改。
2. 填写该服务商的 API 密钥，点击“获取模型”。无需预先保存，也无需先填写模型名称。
3. 从服务实时返回的列表中选择模型；列表较长时可以搜索。列表获取失败或未返回目标型号时，可勾选“手动填写模型名称”。
4. 点击“测试模型”验证文字回复，成功后自动保存并启用本次配置；也可以直接“保存配置”。测试仅发送一句问候，不发送项目正文，可能产生少量模型用量。

各服务商的地址、模型、接口协议与密钥分别保存；切换服务商会加载其已保存配置，保存或测试成功后用于创作。获取模型列表不会更改当前创作配置。创作助手显示当前使用的模型，生成时区分连接、已连接、思考、分段整理和输出，并显示用时。模型列表以账号权限和服务商当时的返回结果为准，请选择支持文字生成的模型。

DeepSeek、MiMo 默认使用 Chat Completions；OpenAI / Codex 默认使用 Responses；Gemini 使用 Google AI Studio 的原生接口。这里的 Codex 指 API 模型接入，需要对应服务的 API 密钥。自定义服务可在“高级设置”选择三种协议之一。支持 HTTPS 服务，也支持本机 HTTP 接口（例如 `http://127.0.0.1:11434/v1`）。软件没有内置密钥或赠送额度。

API 地址、模型、接口协议与密钥使用 Windows 系统保护机制整体加密保存在本机，不写进项目备份。更改服务地址时，旧地址的密钥不会用于新地址，请重新填写。生成会将“查看将发送的资料”中显示的内容发送到该接口；可以先检查资料范围。旧版配置首次读取时自动迁移为加密配置，保留模型、密钥和协议。旧版程序不能读取新版加密配置，请使用新版启动脚本。

AI 支持：人物与世界规则建议、故事大纲、章节拆分、续写、整章改写、章节事实摘要、当前章节矛盾检查与新设定提议。可停止生成；失败后可重新点击生成。中断的输出仅供参考，不会被当作完整结果自动采纳。

在“辅助写作”的摘要区点击“生成摘要候选”，预览后采纳，摘要会供后续章节参考。生成过程中修改过正文或摘要时，需要重新生成，避免旧结果覆盖手动编辑。

检查记录按章节保存，多次检查会追加记录，保留已处理状态。勾选“显示全部章节与旧版记录”可集中查看；旧版未标记章节的记录保留为“未关联章节”。正文在检查后变化时，需要重新检查才能采纳。

已确认的现有设定更新可以在“确认设定”点击“撤销这次设定更新”，恢复更新前的正文并保留撤销记录。设定已有后续编辑时会阻止撤销，需对照原文手动调整。新增设定仍由世界资料库管理。

人物与规则从 02 的已确认资料自动带入 03 及后续步骤；写作时还可勾选地点、物品等补充资料。未填写摘要的前章不会自动读取全文。每次可以预览当前阶段将发送的资料。

长资料超过约 1.6 万字符时，会按约 1 万字符分段发送并逐段提炼，必要时再合并压缩，最后执行创作任务。所有原始段落都会发送，原稿不会截断或改动；提炼摘要可能遗漏细节，因此分段生成后可展开“查看本次分段整理资料”核对实际依据。长资料需要多次请求，可随时停止；中途失败不会采纳半成品。检查结果仍需作者对照原文确认。

DeepSeek 默认关闭深度思考，直接生成创作内容，避免推理消耗完回复额度。生成回复额度为 8192 Token；若回复到限会明确提示“输出上限”，保留已收到的部分供手动参考。建议每次生成少量章节、逐章写作；输入超过服务商限制时会单独提示“输入资料”。

创作生成内容先显示在候选区。大纲与正文采纳前自动保存版本；章节拆分追加新章节；人物、规则及检查中的新事实需逐条确认。若生成后作者修改了目标内容，系统会阻止覆盖。房间自动回复启用时直接发布对话，主持人可以暂停改为预览发布。

## 保存、版本与迁移

- 项目数据保存在 `%APPDATA%/wdworld/wdworld/projects`（默认 Electron 用户目录；以实际应用配置为准）。桌面版的项目元信息、正文、设定、版本记录及数据库内的图片默认加密为 `project.wdw`；上一轮自动备份 `project.wdw.bak` 和最近项目列表同样加密。不自动上传项目。
- 旧项目在读取或保存时自动迁移，先加密并校验成功，再清除旧明文文件。旧 `.bak` / `.tmp` 恢复副本封存为 `legacy-recovery.wdw`。系统加密不可用或原文件损坏时，会报错并阻止覆盖，不降级为明文。已迁移项目不能使用不支持加密的旧程序打开。
- 每 10 秒自动保存有修改的创作内容，持续输入时也会保存。每个页面都有“保存本页”；右上角保存按钮也可立即保存。各阶段给助手的要求、未提交的人物与规则草稿一并保存。关闭桌面窗口时会等待保存确认，保存失败则保留窗口。
- “版本历史”保留最近 20 个手动或采纳前版本。恢复故事想法、大纲、章节和问题记录，不回滚已经确认的资料库条目；设定更新前的原文保留在确认记录内。
- 生成记录保留最近 30 次。未完成生成不会覆盖已有内容。
- “版本历史 → 导出完整项目备份”可导出明文 JSON，包含小说、版本、资料库、模板以及仍可读取的上传图片，不包含 API 密钥。欢迎页“打开本地备份”可导入为新项目。请妥善保管导出文件；更换电脑或系统账号前先导出，本机密文依赖原系统账号和应用加密环境，单独复制项目目录不能保证解密。
- 兼容旧版备份，但未包含的图片或模板无法恢复。备份格式版本为 5，包含项目模式、各模式草稿、角色卡、场景卡、副本、世界书与推演记录；导入时重建条目关联。格式版本与软件发布编号独立，1.7.0 兼容此前本地 1.11 的项目数据。局域网档案单独加密保存，可从房间历史导出。
- 桌面包目前是本地未签名版本，没有自动更新。

## 软件语言与默认保护

软件默认简体中文。使用页面右上角语言选择器或“设置 → 语言 → English”切换，原生菜单、世界观工具、创作流程、设置窗口和提示同时切换，并在重启后保留。用户输入的项目名称、正文、角色设定、导入模板和 AI 输出保持原文。局域网玩家可在自己的浏览器独立选择语言。

“设置 → 本地数据保护”可查看保护说明与当前系统加密可用状态。项目采用 AES-256-GCM 认证加密，随机密钥由操作系统保护；密钥不会交给创作页面。页面启用沙箱、上下文隔离与内容安全策略，默认拒绝摄像头、麦克风、位置及设备权限，校验本地消息来源并拦截非应用页面跳转与危险外部协议。AI 请求继续要求 HTTPS（本机 HTTP 模型除外），禁止自动重定向。

这些措施保护本地静态文件并减少页面权限，不是账号登录锁，也无法阻止已控制当前系统账号的程序。导出的文件、用户原始素材及网页版浏览器存储不属于桌面加密范围。

实现依据：[Electron 安全建议](https://www.electronjs.org/docs/latest/tutorial/security)、[系统密钥保护](https://www.electronjs.org/docs/latest/api/safe-storage)。

## 从源码运行

接口适配依据：[MiMo 模型列表](https://mimo.mi.com/docs/en-US/api/model/list-models)、[MiMo 对话接口](https://mimo.mi.com/docs/en-US/api/chat/openai-api)、[DeepSeek 模型列表](https://api-docs.deepseek.com/api/list-models/)、[OpenAI 模型列表](https://developers.openai.com/api/reference/resources/models/methods/list)、[OpenAI Responses 流式输出](https://developers.openai.com/api/docs/guides/streaming-responses)、[Gemini 模型列表](https://ai.google.dev/api/models)、[Gemini 内容生成](https://ai.google.dev/api/generate-content)。

```powershell
npm.cmd ci
npm.cmd run desktop
```

`desktop` 会先构建再启动桌面程序。`npm.cmd run package` 生成独立桌面目录；`npm.cmd run electron:build` 可生成安装包。网页开发仍使用 `npm.cmd run dev`，网页端支持手动创作，AI 请求仅在桌面端启用。

`npm.cmd run test:desktop` 使用隔离目录和模拟服务验证完整流程及长文本分段，不调用真实模型。`scripts/test-live-ai.js` 必须显式设置 `WDWORLD_LIVE_AI=1` 才运行：使用本机已保存的配置发送一个短测试故事，可能产生少量 API 用量，不读取项目正文，也不输出密钥。

`npm.cmd run test:studio` 验证默认世界观入口、各模式辅助创作、角色卡与世界书导出、玩家背景隔离、世界变更的确认与撤销，以及重启恢复。

`npm.cmd run test:world` 验证整套世界与设定入库；`npm.cmd run test:lan` 验证双玩家、权限隔离和语言；`npm.cmd run test:automation` 验证后台自动回复、场景卡、副本、主持人干预和重启恢复。均使用隔离目录及模拟服务。开发结构与检查命令见 [README](../README.md)，公开发布变更见 [更新记录](../CHANGELOG.md)。
